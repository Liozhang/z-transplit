# 原型：按区域真正删除 PDF 文字（RegionTextRemover）

本目录是一个可行性原型：验证"译文 PDF 不再使用白色遮罩，而是把已翻译段落的原文从
内容流中真正删除"这一技术路线。结论与数据见文末。

## 目录结构

- `src/RegionTextRemover.java` — 核心：内容流解析 + 逐字形判定 + 重写
- `src/Fixtures.java` — 生成八个测试夹具 PDF 与区域文件
- `src/Probe.java` — 验收探针：整页像素对比 + 文字残留统计
- `src/ResidueDump.java` — 残留字形明细（归因用）
- `src/FmDump.java`、`src/FmDeepDump.java`、`src/PageFontDump.java`、`src/PageStreamDump.java` — 诊断工具
- `lib/` — PDFBox 2.0.37、FontBox 2.0.37、commons-logging 1.2（Maven 中央仓库下载）
- `work/` — 夹具、真实论文（arXiv 1706.03762）与全部产物（不入库）

## 编译与运行

```bash
CP="lib/pdfbox-2.0.37.jar;lib/fontbox-2.0.37.jar;lib/commons-logging-1.2.jar"
javac -encoding UTF-8 -cp "$CP" -d build src/*.java
java -cp "build;$CP" Fixtures                                # 生成夹具
java -cp "build;$CP" RegionTextRemover 输入.pdf 区域文件 输出.pdf
java -cp "build;$CP" Probe 原.pdf 删后.pdf 区域文件 --png-prefix work/x
```

区域文件每行：`页码 x0 y0 x1 y1`（PDF 用户坐标，原点左下，页码从 1 起）。

## 核心设计

1. **逐字形中点判定**：解析内容流，用自带的三维仿射矩阵（列向量语义，
   设备坐标 = 调用变换 × 文字矩阵 × 点）跟踪每个字形的基线区间，
   中点落入边界框的字形删除。字距数字（TJ 数组中的数）按同样规则单独判定。
2. **位置保持**：解析器状态按原流推进量完整重放（无论删留）；改写后的 TJ
   用位移数字补足被丢弃字形的推进量；行撇号算子（`'` 与 `"`）补 `T*`；
   双引号算子（`"`）补 `Tw/Tc`。保证保留的文字一像素都不挪动。
3. **部分重建**：一个算子里部分字形被删时，重建为新的 TJ 数组，
   缺口用位移数字补齐（在 kerning 夹具中验证）。
4. **表单递归**：在 `Do` 算子的调用点处理表单对象与透明组，
   区域先经"调用点变换 × 表单 /Matrix"的逆变换映射进表单坐标系。
   同一表单流只按首次调用处理一次。
5. **保守护栏**：渲染模式 7（文字作剪裁路径）不删；含内联图像（BI..EI）的
   流整条跳过；字体缺失时按半宽估算推进量；单表单失败不影响整体。

## 测试结果

| 夹具 | 覆盖风险 | 框外像素差异 | 残留 |
| --- | --- | --- | --- |
| single | 单栏连续段落 | 0/1144128 | 0/691 |
| twocol | 双栏折行 + 插图 | 0/994270 | 0/1335 |
| cjk | 嵌入微软雅黑的中英混排 | 0/1178233 | 0/171 |
| graphics | 文字与色块、下划线、贯穿表格线共存 | 0/1163633 | 0/422 |
| invisible | 渲染模式 3 的不可见文字（识别层） | 0/1250040 | 0/42 |
| rotate90 | /Rotate 90 页面 | 0/1253151 | 0/276 |
| sequential | 单一文字块内连续推进无重定位 | 0/1319560 | 0/41 |

### 开发过程中发现并修复的缺陷

1. 文字显示算子处理后未把推进量写回文字矩阵，导致同一文字块内后续算子
   全部错位（sequential 夹具暴露）。
2. **矩阵乘法约定错误（最关键）**：自研矩阵的乘法按行向量约定合成，
   而坐标使用按列向量语义。页面层为恒等矩阵时两者等价（夹具全部通过），
   一旦缩放与平移同时出现（真实论文的图表表单），位置整体漂移——
   ResNet 表格文字坐标偏差达 190 磅。已改为严格的列向量积。
3. 表单改写引发渲染异常：改写含透明组的图形表单后，个别图形的白色背景
   渲染为黑色（BERT 架构图暴露）。最终方案：表单内部文字一律不改写。
4. 探针自身三处缺陷：边界框膨胀环带误计为框外、旋转页坐标空间错配、
   像素比较只遍历框附近导致框外指标恒为空集。

## 最终设计（保守混合模式）

只删除页面内容流（第 0 层）中的文字；表单与透明组内部的文字一律保留，
交由现有遮罩路径覆盖。理由：

1. 六篇文献的正文文字全部位于页面内容流，位置精确（恒等变换），
   删除零风险——LIGO 与 GPT-3 两篇达到框外零差异、残留近零。
2. 图形内部文字（图表轴标签、架构图注记）嵌套坐标系复杂，
   个别图形改写后有渲染异常；保留它们交由遮罩兜底，
   与现有管线行为完全一致，零回归。
3. 删除的正文在删后文件中不再可搜索、不可复制，
   消除了遮罩方案"原文埋在文件里"的问题。

## 已知限制

1. 图形表单内部的文字当前保留（由遮罩覆盖）：若希望图形文字也真正删除，
   需先解决嵌套表单改写的渲染异常（BERT 黑色色块问题），
   并校准多层嵌套的坐标链（ResNet 图 1 标签的残余偏移）。
2. 含内联图像（BI..EI）的内容流整条跳过（当前六篇均未触发）。
3. Type3 字体、奇异变换等边角按保守策略跳过。

## 接入主流程的建议

可行性已验证，建议以"删除器前置 + 遮罩兜底"的混合模式接入：
OpenDataLoader 边界框先交删除器清理页面层原文，
再走现有 pdf-lib 叠加流程；遮罩照旧绘制（覆盖图形文字与兜底）。
工程化清单：工具 jar 的构建与来源校验（复用 `check:jar` 机制）、
TS 侧适配器（区域从 OpenDataLoader 分析结果直通）、失败分类与回退、
旋转页与现有渲染器的旋转限制对齐。
